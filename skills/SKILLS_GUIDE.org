* Overview

Sygaldry ships *repo-scoped skills* under =skills/=.  Each skill is a
self-contained directory with documentation (=SKILL.md=), agent metadata
(=agents/openai.yaml=), and supporting scripts/assets.

Skills are validated locally before promotion to a global =$CODEX_HOME/skills=
install.  Until promoted, run everything from the repo checkout.

| Skill                            | Purpose                                             | Status   |
|----------------------------------+-----------------------------------------------------+----------|
| =zephyr=                           | GPU containers, MLSys envs, LLM experiments, vendor | Deferred |
| =codex-headless=                   | Headless Codex CLI runs                             | Wave 1   |
| =codex-dev-loop=                   | Two-agent implement-review-test loop                | Wave 1   |
| =nvidia-container-troubleshooting= | Diagnose GPU/Docker issues                          | Local    |
| =local-skills-sync=                | Keep =LOCAL_SKILLS.md= in sync with filesystem        | Local    |

* Zephyr (Unified GPU Skill)
:PROPERTIES:
:SKILL_DIR: skills/zephyr
:END:

The =zephyr= skill consolidates four capabilities into one directory:
container exec, MLSys environment management, LLM experiments, and
cross-repo adaptation/vendoring.

** Quick Start

#+begin_src bash
# 1. Verify the Spack environment + GPU
./container/launch_container.sh --entrypoint=verify-spack.sh

# 2. Run a one-off Python command
./container/launch_container.sh bash -lc \
  "python -c 'import torch; print(torch.cuda.is_available())'"

# 3. Launch a tracked job
tools/zephyr_job run --project-id myproj --job train -- "python train.py"

# 4. Check status (low-token, safe for agents)
tools/zephyr_job status --project-id myproj --job train
#+end_src

** Container Exec

Run commands inside the Zephyr container with the Spack environment
(PyTorch, JAX, CUDA) automatically activated.

*** Running jobs

#+begin_src bash
# Start a job
tools/zephyr_job run --project-id <id> --job <name> -- <command>

# Monitor
tools/zephyr_job status --project-id <id> --job <name>
tools/zephyr_job health --project-id <id> --job <name>
tools/zephyr_job tail   --project-id <id> --job <name> --lines 40

# Stop
tools/zephyr_job stop   --project-id <id> --job <name>
#+end_src

*** Multi-container isolation

Use distinct =SYGALDRY_PROJECT_ID= values to isolate home dirs, caches,
and job artifacts:

#+begin_src bash
SYGALDRY_PROJECT_ID=experiment-a ./container/launch_container.sh
SYGALDRY_PROJECT_ID=experiment-b ./container/launch_container.sh
#+end_src

Each project ID maps to its own host root at:
=/mnt/data_infra/zephyr_container_infra/projects/<project_id>/=

*** Job artifact locations

| Artifact  | Path                                                          |
|-----------+---------------------------------------------------------------|
| JSONL log | =projects/<id>/outputs/.run-metadata/<run_id>/<job>-<ts>.jsonl= |
| Status    | =projects/<id>/outputs/.run-metadata/<run_id>/<job>.status=     |
| Raw log   | =projects/<id>/runs/<run_id>/raw/<job>-<ts>.log=                |

All paths are under =/mnt/data_infra/zephyr_container_infra/=.

*** Installing Python packages

#+begin_src bash
# Prefer Spack for heavy scientific deps (torch, jax, numpy).
# Use uv only for pure-Python packages:
./container/launch_container.sh bash -lc \
  "uv venv && source .venv/bin/activate && uv add transformers datasets"
#+end_src

*** LoRA bootstrap

#+begin_src bash
# Create the pinned HF venv (uses Spack torch, no override)
./container/launch_container.sh --entrypoint=hf-lora-setup.sh

# Run LoRA training
tools/zephyr_job run --project-id myproj --job hf-lora -- \
  "cd /workspace/<repo> && .venv-hf-lora/bin/hf-lora-python train.py"
#+end_src

*** Triage checklist (when a job looks stuck)

1. Check PID: ~tools/zephyr_job health --project-id <id> --job <name>~
2. Check heartbeat timestamp in status output
3. Tail last 40 lines: ~tools/zephyr_job tail --project-id <id> --job <name> --lines 40~
4. Look for =FAILED rc=...= in the final log lines

** Repo Adaptation (Vendoring)

Package the Zephyr container runtime as a hermetic kit for other repos.

*** Core policy

- Consumer repos pin images by digest (=@sha256:...=).
- Consumer repos never rebuild Spack.
- Spack owns heavy packages; uv layers app deps.
- Runtime must not depend on the sygaldry checkout.

*** Vendor infra into a target repo

#+begin_src bash
SKILL_DIR=skills/zephyr

"$SKILL_DIR/scripts/zephyr_vendor_infra.sh" install \
  --target-repo /path/to/target-repo \
  --snapshot-ref ghcr.io/phi9t/sygaldry/zephyr:spack-YYYYMMDD@sha256:<digest> \
  --image-mode auto \
  --runtime-image myrepo/zephyr:dev

# Later: update or check
"$SKILL_DIR/scripts/zephyr_vendor_infra.sh" update --target-repo /path/to/target-repo
"$SKILL_DIR/scripts/zephyr_vendor_infra.sh" check  --target-repo /path/to/target-repo
#+end_src

*** Package for distribution

#+begin_src bash
# Infra package (container runtime)
skills/zephyr/scripts/package_infra.sh \
  --out-dir /tmp/skill-dist \
  --version 2026.02.25 \
  --snapshot-ref ghcr.io/phi9t/sygaldry/zephyr:spack-YYYYMMDD@sha256:<digest>

# MLSys package (UV overlay environments)
skills/zephyr/scripts/package_mlsys.sh \
  --out-dir /tmp/zephyr-mlsys-dist \
  --version 2026.02.25 \
  --smoke-mode skip
#+end_src

*** Hermetic validation

#+begin_src bash

#+end_src

* Skill Lifecycle

** Directory structure

Every skill follows this layout:

#+begin_example
skills/<name>/
  SKILL.md              # Docs + frontmatter (name, description)
  VALIDATION.md         # Optional: validation scenarios
  agents/openai.yaml    # Agent metadata
  scripts/              # Executable scripts
  assets/               # Vendored runtime files
  references/           # Schemas, configs
  envs/                 # Environment definitions (zephyr only)
  portable/             # Portable launchers (zephyr only)
#+end_example

** Validation commands

#+begin_src bash
# Hermetic audit (checks for repo-coupled paths)
python3 skills/hermetic-skill-audit.py skills/<name>

# Sync check (LOCAL_SKILLS.md matches filesystem)
python3 skills/local-skills-sync/scripts/sync_local_skills.py --check

# Shell lint
shellcheck -s bash -S warning skills/<name>/scripts/*.sh

# Python compile check
python3 -m py_compile skills/<name>/scripts/*.py
#+end_src

** Promotion workflow

1. Vendor all materials into the skill directory
2. Replace repo-relative paths with =$CODEX_HOME/skills/<name>= paths
3. Pass all hard gates (packaging, hermeticity, interface, validation, smoke)
4. Install into =$CODEX_HOME/skills=
5. Smoke test from outside this repo
6. Restart Codex to load changes

Current promotion status:
- *Wave 1* (ready): =codex-headless=, =codex-dev-loop=
- *Deferred* (repo-coupled): =zephyr=
