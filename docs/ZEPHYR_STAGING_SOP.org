* Overview

Stage the Spack environment (PyTorch latest), build 7 MLSys baked images
sequentially, verify each with the 5-test suite (T1–T5), and publish to
GHCR with latest + dated tags. All builds are GPU-only (NVIDIA runtime
required).

Full SOP + incident log:
=docs/ZEPHYR_STAGING_END_TO_END_SOP_AND_OPERATION_LOG_2026-02-22.md=

* Pipeline Steps

** Stage Spack

#+begin_src bash
SYGALDRY_PROJECT_ID=zephyr-pytorch-latest-staging \
SYGALDRY_BUILD_ROLE=builder \
./container/launch_container.sh bash -lc '
  cd /workspace/pkg/zephyr/staging/pytorch_latest
  ./build.sh
'
#+end_src

*Pass:* =final_status.json= has ~"status": "ok"~ and =py-torch= has =+nccl +distributed=.

*Artifacts:*
- =outputs/spack_stage/<run_id>/logs/final_status.json=
- =outputs/spack_stage/<run_id>/logs/concretize_report.json=
- =outputs/spack_stage/<run_id>/logs/install.log=

*Must-have variants:*
- =py-torch@2.9.0+cuda+distributed+nccl cuda_arch=61,75,80,86,89,90=
- =py-jax@0.7.0=, =py-jaxlib@0.7.0+cuda=, =py-triton@3.4.0=

If =py-torch= lacks =+nccl= or =+distributed=, the pipeline exits 16. *Do not proceed to image builds.*

** Build MLSys Images

Build *one at a time* — parallel builds are prohibited (Docker daemon
contention, GPU for verification, disk I/O on 60 GB images).

#+begin_src bash
./container/snapshot_mlsys.sh hf-transformers
./container/snapshot_mlsys.sh hf-datasets
./container/snapshot_mlsys.sh vllm
./container/snapshot_mlsys.sh sglang
./container/snapshot_mlsys.sh torchtitan
./container/snapshot_mlsys.sh megatronlm
./container/snapshot_mlsys.sh llm-serving-all
#+end_src

*Per-env pass criteria:*
- Build succeeds
- Verification passes (14/14)
- No =not ok= lines in output

*On failure:* Fix, rebuild same env. Do not skip. Max 3 retries before escalation.

** Verify

Verification runs automatically via the =--verify= flag (default). For manual
standalone verification:

#+begin_src bash
./container/verify_mlsys.sh sygaldry/zephyr:<tag>
#+end_src

*** Test Suite

| Test | Name            | GPU | Checks                                           |
|------+-----------------+-----+--------------------------------------------------|
| T1   | Image Metadata  | No  | Labels, ENV vars, inherited Spack label          |
| T2   | Filesystem      | No  | Venv root, =.default-env=, =.manifest=, =bin/activate= |
| T3   | Provenance      | No  | Spack vs UV ownership per env YAML (=--no-gpu=)    |
| T4   | GPU Functional  | Yes | Import checks with CUDA assertions (=--gpu-only=)  |
| T5   | Auto-Activation | Yes | =VIRTUAL_ENV= set on =docker run=, import succeeds   |

*** Failure Recovery

| Test | Likely Cause                | Fix                                |
|------+-----------------------------+------------------------------------|
| T1   | Dockerfile label/ENV issue  | Fix =mlsys_venv.dockerfile=          |
| T2   | Build script issue          | Check =uv-env-build.sh=              |
| T3   | Package provenance mismatch | Update env YAML =provenance= section |
| T4   | Import or ABI error         | Check overrides, rebuild           |
| T5   | =.bashrc= integration issue   | Check dockerfile =.bashrc= append    |

** Publish to GHCR

*** Push latest tags (integrated)

#+begin_src bash
./container/snapshot_mlsys.sh <env> --push --registry ghcr.io/phi9t/sygaldry
#+end_src

Pushes both =:tag= (latest) and =:tag-YYYYMMDD= (dated).

*** Dated tags via imagetools (when direct push stalls)

For 60 GB images, =docker push= of dated tags often stalls/times out. Use
=imagetools create= to alias the already-pushed manifest (sub-second, no
re-upload):

#+begin_src bash
docker buildx imagetools create \
  --tag ghcr.io/phi9t/sygaldry/zephyr:<tag>-YYYYMMDD \
  ghcr.io/phi9t/sygaldry/zephyr:<tag>
#+end_src

Batch all 7:

#+begin_src bash
for tag in hf hf-datasets vllm sglang torchtitan megatronlm mlsys; do
  docker buildx imagetools create \
    --tag ghcr.io/phi9t/sygaldry/zephyr:${tag}-YYYYMMDD \
    ghcr.io/phi9t/sygaldry/zephyr:${tag}
done
#+end_src

*** Verify remote manifests

for tag in hf hf-datasets vllm sglang torchtitan megatronlm mlsys; do
  docker buildx imagetools inspect ghcr.io/phi9t/sygaldry/zephyr:${tag}

* Gotchas and Sharp Edges

** Build-Time

*** =python-dateutil= 0.0.0 in Spack dist-info (ISS-1 area)

~Symptom:~ UV refuses to install packages needing =python-dateutil>=2.8.2=
because the Spack-installed dist-info reports version =0.0.0=.

*Cause:* Spack's =py-python-dateutil= writes broken dist-info metadata.

*Fix:* The Dockerfile patches dist-info inline (=sed= + =mv= to set version
=2.8.2=). If Spack fixes this upstream, remove the patch from
=mlsys_venv.dockerfile=.

*** =transformer-engine[pytorch]= requires GPU at Docker build (ISS-4 related)

~Symptom:~ Installing =transformer-engine[pytorch]= extra fails during
=docker build= because =pytorch= extras trigger GPU initialization.

*Cause:* The =[pytorch]= extra runs CUDA calls at install time.

*Fix:* Install =[core]= only in the Dockerfile. The =[pytorch]= extra must be
installed post-build inside a =docker run= with GPU. Current megatronlm env
uses =[core]= and this is sufficient.

*** =megatron-core= import triggers GPU init (ISS-4)

~Symptom:~ =import megatron= crashes in verification (T4/T5) because
=transformer_engine= initialization attempts GPU operations.

*Cause:* Module-level import of =megatron= pulls in =transformer_engine=
which runs CUDA calls.

*Fix:* Verification uses =importlib.metadata.version("megatron-core")= instead
of direct import. This confirms package presence without triggering GPU init.
Changed in both env YAML =gpu_functional= script and =verify_mlsys.sh= T5
import check.

*** =networkx= missing as transitive dep for vLLM (ISS-3)

~Symptom:~ =import vllm= fails with =ModuleNotFoundError: No module named 'networkx'=.
T3, T4, T5 all fail.

*Cause:* =networkx= is a transitive dependency of vLLM that UV does not
automatically resolve in the constrained Spack environment.

*Fix:* Add =networkx= explicitly to package lists in both =vllm= and
=llm-serving-all= env YAMLs. Watch for similar transitive deps in future
vLLM versions.

** Verification

*** =pandas= provenance ownership (ISS-2)

~Symptom:~ T3 provenance test reports =not ok - pandas from Spack view=
on hf-datasets image.

*Cause:* Env YAML had =pandas= listed under =spack_provenance=, but Spack
does not provide pandas — UV correctly installs its own copy.

*Fix:* Move =pandas= from =spack= provenance to =uv= provenance in
hf-datasets YAML. Always verify provenance declarations match reality by
checking whether a package exists in =/opt/spack_store/view/=.

*** PyTorch concretization without =+nccl +distributed= (ISS-1)

~Symptom:~ =py-torch= concretized without required variant flags.

*Cause:* No gate existed to verify variant flags after concretization.

*Fix:* Added inline Python gate at step =pytorch_variants= in
=tools/zephyr_stage_spack.sh= (exit code 16). Reads =spack.lock=, asserts
=+nccl= and =+distributed= present. Now enforced on every staging run.

** Registry

*** Docker Hub broken for large images (ISS-7)

~Symptom:~ =docker push= to Docker Hub fails with permission denied or stalls.

*Cause:* Docker Hub rate limits / free-tier limitations on 60+ GB images.

*Fix:* Use GHCR exclusively (=ghcr.io/phi9t/sygaldry=). Docker Hub is not
supported for this project.

*** Dated tag push stalls with =rc=124= timeout (ISS-8)

~Symptom:~ =docker push= of dated tags (=:tag-YYYYMMDD=) stalls and times out
even though identical layers already exist under the =:tag= reference.

*Cause:* =docker push= re-uploads all layers for a new tag even when they
already exist in the same repo.

*Fix:* Use =docker buildx imagetools create= to alias the already-pushed
manifest. This is a manifest-only operation (sub-second). *Always push latest
first*, then create dated tags as aliases.

** Spack-Specific

*** BuildKit export phase takes ~200s for 60 GB images (ISS-5)

~Symptom:~ Builds appear hung during the export phase.

*Cause:* Large image layers require significant I/O. Full project directory
was sent as build context before =.dockerignore= was added (ISS-6).

*Fix:* (1) =.dockerignore= excludes =outputs/=, =.git/=, =.venv/=,
=__pycache__/=. (2) Minimal-context workaround copies only required dirs to
a temp context before build. (3) BuildKit cache mount for UV cache avoids
baking download cache into layer. The ~200s export is a Docker/BuildKit
limitation — accept the wait.

*** Docker build sends multi-GB context (ISS-6)

~Symptom:~ Build context transfer is slow, sending =outputs/=, =.git/=, etc.

*Cause:* Missing =.dockerignore= at repo root.

*Fix:* =.dockerignore= now present. Verify with =test -f .dockerignore=
before building.
